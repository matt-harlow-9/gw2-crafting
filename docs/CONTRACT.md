# GW2 Crafting Profit Finder: interface contract

A static, no-backend web app. Plain ES modules (`type: module`), no build step, no dependencies.
Runs with a one-line static server (`python3 -m http.server`). Tests run with `node --test`.

Public GW2 API: https://api.guildwars2.com/v2 (no key needed except for owned materials).

## Ownership (each agent edits ONLY its own files)

| Layer | Files |
|---|---|
| Data | `src/data.js`, `src/cache.js`, `test/data.test.js` |
| Core | `src/pricing.js`, `test/pricing.test.js` |
| UI | `index.html`, `src/app.js`, `style.css`, `src/mock.js` |

Do not edit this file or another layer's files. If the contract is wrong or missing something,
say so in your final report instead of changing it.

## Shared types (plain objects). All prices are integer copper.

```
Ingredient { type: 'Item' | 'Currency' | 'GuildUpgrade', id: number, count: number }

Recipe {
  id: number,
  outputItemId: number,
  outputCount: number,            // output_item_count, default 1
  disciplines: string[],          // e.g. ['Weaponsmith', 'Armorsmith']
  minRating: number,
  ingredients: Ingredient[],
  flags: string[]                 // e.g. 'AutoLearned', 'LearnedFromItem'
}

Item { id: number, name: string, icon: string, rarity: string, flags: string[] }
  // flags include 'AccountBound', 'SoulbindOnAcquire', 'NoSell' when the API reports them

Price {
  buyPrice: number,               // highest buy order; 0 means no orders
  sellPrice: number,              // lowest sell listing; 0 means no listings
  buyQuantity: number,            // units across buy orders
  sellQuantity: number            // units across sell listings
}

GameData {
  recipes: Recipe[],
  items: Map<number, Item>,       // every item id that appears as a recipe output or ingredient
  prices: Map<number, Price>      // only tradable items; missing key = not tradable
}
```

## Data layer: `src/data.js`

```
loadGameData({ onProgress?, signal? }) -> Promise<GameData>
  // onProgress({ stage: 'recipes'|'items'|'prices', done: number, total: number })
  // Must use recipes with ?v=latest (the default schema drops Currency and GuildUpgrade
  // ingredients). Bulk ?ids= requests of at most 200. Respect the 600 requests/minute limit.
  // 206 is a valid partial response; 404 "all ids provided are invalid" means an empty list.
  // Recipes and items are cached via src/cache.js (IndexedDB, falling back to memory) with a
  // long TTL (days). Prices are cached for at most 5 minutes.

refreshPrices({ signal? }) -> Promise<Map<number, Price>>
  // Re-fetch prices only, for the item ids in the cached game data.

loadOwnedMaterials(apiKey: string, { signal? }) -> Promise<Map<number, number>>
  // item id -> total count, summed over account/materials, account/bank and account/inventory
  // (shared inventory). Slots in bank/inventory can be null. Never store or log the key.
  // Rejects with an Error whose message says which endpoint failed (bad key, missing scope).
```

`src/cache.js` exports `cacheGet(key)`, `cacheSet(key, value, ttlMs)` (both async). Every
browser-only API (IndexedDB, localStorage, fetch) must be reachable via a parameter or a
guarded global so `node --test` can run the tests with an injected `fetch`. Accept `fetchImpl`
as an optional field in the options of the three functions above.

`loadSalesVelocity({ signal?, fetchImpl?, cache? }) -> Promise<Map<number, { sold1d, sold7d }>>`
fetches estimated sell-side sales from the Datawars2 bulk endpoint (cached 30 minutes). It never
throws: any network, HTTP or shape problem yields an empty Map (`size === 0` means unavailable).
`computeRows` accepts an optional `options.velocity` (that Map) and adds `Row.soldPerDay`
(`sold7d / 7`, rounded; `0` if the item is absent from a non-empty Map; `null` if no data).

## Pricing core: `src/pricing.js`

Pure functions, no I/O, no DOM.

```
TP_LISTING_FEE = 0.05, TP_SALE_FEE = 0.10

netSellPrice(sellPrice: number) -> number
  // sellPrice - max(1, ceil(sellPrice * 0.05)) - max(1, ceil(sellPrice * 0.10)); 0 if sellPrice is 0

computeRows(gameData, options) -> Row[]
  options = {
    ingredientPricing: 'buyOrder' | 'instantBuy',  // buyOrder uses buyPrice, instantBuy uses sellPrice
    hideUnlockRequired: boolean,                    // drop recipes lacking 'AutoLearned'
    owned?: Map<number, number>                     // item id -> count; owned units cost 0
  }
  // One Row per recipe whose output is tradable and whose ingredients all resolve.
  // An ingredient resolves if it is a tradable Item (has a price), or an Item that is itself
  // craftable (then use the cheaper of buying and crafting, recursively; guard cycles).
  // Recipes needing Currency/GuildUpgrade ingredients, or an Item with no price and no
  // recipe, are excluded and counted in the second return value below.
  // Divide the craft cost by outputCount to get a per-unit cost.

Row {
  recipeId: number, itemId: number, name: string, icon: string, rarity: string,
  disciplines: string[], minRating: number,
  craftCost: number,        // per output unit
  grossSellPrice: number,   // the item's sellPrice
  netSellPrice: number,     // after fees
  profit: number,           // netSellPrice - craftCost
  margin: number,           // profit / craftCost (0 if craftCost is 0)
  buyQuantity: number, sellQuantity: number,
  usesOwned: boolean        // true if owned materials reduced the cost
}

computeRowsWithExclusions(gameData, options) -> { rows: Row[], excluded: number }

getIngredientTree(gameData, recipeId, options) -> TreeNode
TreeNode {
  itemId: number, name: string, icon: string,
  count: number,                 // total units needed for the whole craft
  mode: 'buy' | 'craft' | 'owned',
  unitCost: number, totalCost: number,
  children: TreeNode[]           // only when mode === 'craft'
}
```

## UI: `index.html`, `src/app.js`, `style.css`, `src/mock.js`

Imports `loadGameData`, `refreshPrices`, `loadOwnedMaterials` from `./data.js` and
`computeRowsWithExclusions`, `getIngredientTree` from `./pricing.js`.
`src/mock.js` exports a small `mockGameData` object matching `GameData` (about 20 recipes, with
at least one multi-level recipe and one with outputCount > 1) so the UI can be built and checked
before the real modules exist. Use a `?mock` query parameter to switch to it.

Required: sortable table (profit, margin, volume), filters for discipline and minimum volume,
ingredient pricing toggle (buy order / instant buy), hide-unlock-required toggle, an API key
field for owned materials (kept in memory only, not saved), a detail view with the ingredient
tree, loading progress from `onProgress`, a price refresh button, an excluded-recipes count,
coin formatting (gold/silver/copper), and light and dark themes. Render large tables smoothly.
